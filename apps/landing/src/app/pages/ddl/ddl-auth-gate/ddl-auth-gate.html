Private content renders here, and only here.

signed in · under the header

Private pages form one group. A new private page is one entry in PRIVATE_ROUTES. The whole area lives in pages/private/ (routes, frame, sign-in page). The group gives each page the rest: the gate (inside an ng-template, so nothing private is created before sign-in), an HttpClient that sends the token on API calls, RenderMode.Client and X-Robots-Tag: noindex. The feature itself holds no auth code.

The session is app-wide state, restored once per page load. The header stays the same for every visitor. Sign-in is the "Sign in" entry in the More menu (its own Account section, stacked under Documents), which opens /sign-in, or the gate on any private page. Sign-out is landing-session-bar, a slim row the private frame puts right under the header once signed in. Public pages never show it, even for the signed-in Owner. The account is the console's, and so is the session: prod cookies are scoped to the parent domain, so signing in or out here does the same on the console.
