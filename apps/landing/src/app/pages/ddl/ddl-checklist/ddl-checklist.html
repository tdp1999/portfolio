Picked: Compact. One line per phase, collapsible, Do and Check as columns. The stage above is landing-checklist-board, the same component the run page at /checklist/:id renders.

Not picked: Document (phases as chapters with a progress rail on the left) read well top to bottom but made sixty rows long to scan; Focus (one phase at a time behind a stepper) hid the rest of the run. A phase board was never offered: eight phases with sentence-long rows give columns under 280px.

Click targets: a row's text is its checkbox's label, so a click on it ticks or unticks the row, as on a native checkbox; a ref inside it only opens the ref, and a click that ends a text selection does nothing. A click on a phase's title line folds or opens it, like the chevron (not in edit mode, where every phase stays open).

Shared rules: the × marks a task skipped, which counts as complete but leaves the checkbox empty; the undo icon returns it to todo. The role filter dims rows whose Do and Check both leave the role out, it never hides them. A ref chip opens its section in the panel, read-only, with the file to edit it in.

Source: the lanes and the lookup table come from the ctx plugin repo. The docs list refreshes itself every 10 minutes, and Update checklist on the templates page reads the repo at once. A run keeps the copy it was made from.

Work vs edit: ticking, skipping and notes are always on, since they are the work. Structure changes (drag, edit text, add, delete) wait behind the pen, so the working view stays calm. Edit mode works on a draft: no structure change reaches the run until Save, and Cancel puts the structure back as it was. A tick, skip or note made while editing still saves at once. Deleting a row or group and checking or unchecking a whole phase ask first. The handle also moves a row from the keyboard: focus it, then press ↑ or ↓.
