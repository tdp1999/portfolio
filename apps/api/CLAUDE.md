# CLAUDE.md — `apps/api`

Guardrails that apply only when working inside the NestJS API. Root `CLAUDE.md` still applies on top of these.

| Rule                         | Action                                                                     | Example                                                                 |
| ---------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **No errors in controllers** | Controllers never throw errors — all error logic in command/query handlers | `if (!user) throw NotFoundError(...)` belongs in handler, not controller |
| **Domain layout: one file, one job** | In `modules/<m>/domain/`: types only in `<m>[-<topic>].types.ts`; `entities/<name>.entity.ts`; `value-objects/<name>.ts` (frozen, private constructor, static factories); `policies/<name>.policy.ts` for a stateless rule set (static-only class). A helper only one class uses is a `private static` method of that class, never a loose exported function the class calls back. Inside each class, sections in this order: `// --- Constants ---` (`static readonly`, private when internal) → `// --- Factory Methods ---` → `// --- Getters ---` → `// --- Rules ---` → `// --- Private ---`. In static methods call the class by name, not `this` (a method passed as `.map(Policy.select)` loses `this`). | Reference: `radar/domain/` (`radar-comment.types.ts`, `value-objects/radar-comment-thread.ts`, `policies/radar-comment-{tier,label}.policy.ts`, `policies/radar-comments-cost.policy.ts`; aggregate: `entities/radar-run.entity.ts` owning `radar-step-run.entity.ts`, saved by `RadarRunRepository.save` which writes only what changed). ❌ one `radar-comments.ts` holding types + regex + loose `labelComments()` + a class ✅ split as above |
